PLAN IMPLEMENTASI HEATMAP SURVEILLANCE LOCATION BERBASIS DATA SKDR
Tanggal: 2026-09-06

TUJUAN
------
Membuat card "Surveillance Location Summary" pada detail-region menjadi
heatmap bulanan berdasarkan wilayah/lokasi yang ada di laporan resmi SKDR
(IBS/EBS), mengikuti country/region yang sedang dipilih. Sidebar sinyal di
samping peta tidak dipakai.

CATATAN TEMUAN PENTING
----------------------
1. Heatmap lama membaca disease_events. Untuk SKDR, angka dapat terpengaruh
   proses NLP. Sumber resmi harus skdr_reports.payload.
2. Field IBS yang umum: kasus, jml_kematian, provinsi, kota, kecamatan.
3. Field EBS yang umum: jml_kasus, jml_kematian, propinsi/provinsi, kota,
   distrik.
4. Jangan mengisi tanggal yang tidak ada dengan tanggal buatan. Laporan tanpa
   report_date tidak masuk matriks bulanan.
5. Jangan memakai daftar negara hardcode. Country harus berasal dari master
   locations.country atau metadata SKDR.

DESAIN ENDPOINT
---------------
Buat endpoint baru agar endpoint ASEAN lama tidak terganggu:

  GET /api/v1/spatial-heatmap/locations

Parameter:
  country=Indonesia       (dinamis dari detail region)
  year=2026
  channel=all|ibs|ebs
  disease=all|<disease>

Response yang disarankan:
  {
    "year": 2026,
    "scope": "location",
    "country": "Indonesia",
    "regions": [
      {
        "name": "Jawa Barat",
        "total_cases": 100,
        "total_deaths": 2,
        "total_events": 10,
        "months": [
          {"month_num": 1, "month_name": "Jan", "cases": 10,
           "deaths": 0, "events": 2, "alerts": 0}
        ]
      }
    ],
    "summary": {"total_regions": 1, "total_cases": 100,
                "total_deaths": 2, "total_events": 10}
  }

QUERY DAN NORMALISASI
---------------------
1. Ambil skdr_reports berdasarkan report_year dan report_date.
2. Parse payload di backend dengan helper json_field_text/json_field_count.
3. Kasus: kasus, jml_kasus, jumlah_kasus, case_count, cases.
4. Kematian: jml_kematian, kematian, jumlah_kematian, death_count, deaths.
5. Lokasi prioritas: kecamatan/distrik, kota/kabupaten, provinsi/propinsi.
   Pilih satu level yang konsisten untuk tampilan (disarankan lokasi terdekat
   yang tersedia; fallback berurutan ke kabupaten/kota lalu provinsi).
6. Ambil report_date sebagai bulan. Jika NULL, skip.
7. Country filter harus menggunakan mapping master locations.country. Untuk
   country yang tidak memiliki mapping, jangan menganggap otomatis Indonesia.
8. Deduplicate SKDR memakai dedupe_key/id; satu laporan hanya dihitung sekali.
9. Channel filter memakai endpoint_name (ibs/ebs).

PERBAIKAN COLLECTOR
-------------------
Pastikan collector-python mengenali semua field SKDR:
  cases  = kasus | jml_kasus | jumlah_kasus | case_count | cases
  deaths = kematian | jml_kematian | jumlah_kematian | death_count | deaths

Jangan menaruh angka resmi hanya di normalized_text lalu meminta NLP
menebaknya kembali. Payload tetap menjadi sumber angka SKDR.

PERBAIKAN FRONTEND
------------------
1. Tambahkan fetchLocationHeatmap() di lib/api.ts.
2. Tambahkan mode "location" pada komponen heatmap atau buat komponen
   RegionalLocationHeatmap terpisah.
3. Detail region mengirim country dinamis dari query country yang sedang
   dibuka, bukan string Indonesia hardcode.
4. Card full-width berada di bawah peta.
5. Pertahankan desain dashboard:
   - Cases / Deaths / CFR
   - 12 kotak bulan
   - legend intensity
   - peak month
   - total cases/deaths
   - popup detail lokasi
6. Pada mode location, jangan tampilkan bendera atau ISO di setiap baris.
   Negara cukup ditampilkan sebagai konteks filter/header.
7. Hapus panel sidebar Location-based Surveillance Signals dari detail region.

VALIDASI CFR DAN DATA
---------------------
- CFR dihitung dari data SKDR: deaths / cases * 100.
- Jangan mengubah nilai cases/deaths mentah.
- Jika deaths > cases, tampilkan warning data-quality di popup/tooltip dan
  catat sebagai anomali; jangan menyembunyikan data sumber.
- Hindari clamp diam-diam karena dapat menutupi masalah sumber.
- Tambahkan query audit:
  SELECT endpoint_name, COUNT(*)
  FROM skdr_reports
  WHERE report_year = <year> AND report_date IS NOT NULL
  GROUP BY endpoint_name;

INDEX YANG DISARANKAN
---------------------
Tambahkan migration baru di database/init, misalnya 045_location_heatmap.sql:
  CREATE INDEX IF NOT EXISTS idx_skdr_reports_heatmap_date
    ON skdr_reports (report_year, report_date, endpoint_name);
  CREATE INDEX IF NOT EXISTS idx_skdr_reports_heatmap_payload
    ON skdr_reports USING GIN (payload);
