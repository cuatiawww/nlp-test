CRAWLER / SCRAPING TECHNICAL INTERVIEW
=====================================

Dokumen ini menggabungkan audit crawler/scraping, architecture, workflow, kemampuan saat ini, deduplikasi, RAW/NLP flow, limitations, assumptions, dan pertanyaan bisnis yang belum dapat dipastikan dari source code.

Audit dilakukan secara read-only. Tidak ada kode, dependency, konfigurasi, atau database yang diubah saat pembuatan dokumen ini.

3. CRAWLING FLOW
----------------

3.1 Direct URL

Frontend services/frontend-next/lib/api.ts mengirim:

POST /api/v1/analyze-url
{
  "url": "...",
  "async": true,
  "force_refresh": false
}

Alur asynchronous utama:

User memasukkan URL
    |
    v
Backend Rust /api/v1/analyze-url
    |
    +--> Cek cache database berdasarkan URL
    |       |
    |       +--> Jika valid: langsung kembalikan hasil lama
    |
    +--> POST /analysis-jobs ke collector
            |
            v
        analysis_jobs table
            |
            v
        analysis-job-worker
            |
            +--> Ambil URL dari Collector /extract-url
            |       |
            |       +--> PDF routing jika PDF
            |       +--> Primary Scrapling/HTTP
            |       +--> Fallback direct HTTP
            |
            +--> Kirim teks ke NLP /nlp/analyze/url
            |       |
            |       +--> Full bounded URL analysis
            |       +--> Rules-only fallback jika NLP gagal
            |
            +--> Simpan hasil
                    |
                    +--> raw_reports
                    +--> disease_events
                    +--> disease_event_locations
                    +--> disease_event_diseases
                    +--> analysis_jobs.result

Jika URL gagal diambil:

- Job menjadi failed.
- Tidak ada hasil NLP.
- Tidak selalu ada RAW final yang tersimpan.

Jika fetching berhasil tetapi full NLP gagal:

- Worker mencoba rules-only analysis.
- Hasil dapat berstatus partial.
- Source content tetap dapat disimpan sebagai RAW untuk review.

Mode synchronous legacy:

Jika client tidak mengirim async=true, struct Rust default-nya adalah synchronous.

Backend Rust
    |
    +--> Collector /extract-url
    +--> NLP /nlp/analyze/url
    +--> Hapus record URL lama
    +--> Insert raw_reports
    +--> Insert disease_events
    +--> Return hasil langsung

Saat ini terdapat dua mode Direct URL:

- Asynchronous: jalur utama frontend saat ini.
- Synchronous: jalur legacy/fallback jika async tidak dikirim atau bernilai false.

Input Manual Crawler disimpan ke crawl_matrix_jobs.

Input:

- disease_concept_ids
- url opsional
- country
- region
- province_city
- date_from
- date_to
- max_articles

Alur active worker:

Manual Crawler API
    |
    v
Validasi disease_concept_ids terhadap disease_concepts aktif
    |
    v
Insert crawl_matrix_jobs dengan status queued
    |
    v
crawl_matrix_jobs worker polling database
    |
    +--> Jika URL langsung tersedia
    |       |
    |       +--> Proses satu URL
    |
    +--> Jika tidak ada URL
            |
            +--> Bentuk query penyakit
            +--> Tambahkan country atau region non-ASEAN
            +--> Request Google News RSS
            +--> Parse XML dengan ElementTree
            +--> Ambil link sampai max_articles

Setiap artikel:

    |
    v
Collector /extract-url
    |
    +--> fetch_mode=http
    +--> Direct HTTP
    +--> Scrapling HTTP fallback
    +--> Tidak menggunakan stealth browser pada jalur ini
    |
    v
NLP /nlp/analyze/surveillance
    |
    +--> Filter penyakit
    +--> Filter negara
    +--> Filter tanggal
    +--> Filter provinsi/kota
    |
    v
Simpan
    |
    +--> raw_reports
    +--> crawl_matrix_rows

Behavior penting:

- Multi-disease dalam query diperlakukan sebagai OR.
- ASEAN dan Global tidak dimasukkan sebagai literal keyword Google News.
- Country dimasukkan ke query jika dipilih.
- Region selain ASEAN dan Global dapat dimasukkan ke query.
- Date range tidak dimasukkan ke query Google News.
- Date range diterapkan setelah artikel di-fetch dan dianalisis.
- max_articles dibatasi API menjadi maksimal 50.
- Limit 500 tidak dapat diterima oleh validasi saat ini.
- Manual Crawler tidak menggunakan RabbitMQ untuk tiap artikel.
- Manual Crawler langsung memanggil Collector dan NLP melalui HTTP.
- Jika artikel tidak cocok filter, artikel dilewati dari crawl_matrix_rows.
- RAW dapat sudah dibuat sebelum filter lokasi/tanggal menghasilkan row.
- Reprocess membaca RAW terkait, menghapus matrix rows lama, lalu persist kembali.

Ada implementasi serupa di services/collector-python/app/crawl_jobs.py, tetapi endpoint sekarang hanya membuat job queued. Eksekusi aktif dilakukan oleh services/worker-python/app/crawl_matrix_jobs.py.

6. DIFFICULT WEBSITE BEHAVIOR
-----------------------------

403, 429, 503:

- Scrapling menandai status tersebut sebagai blocked/challenge.
- Pada mode auto, sistem mencoba stealth fallback.
- Pada fetch_mode=http, blocked response dapat menyebabkan error tanpa browser fallback.
- Direct URL memiliki fallback HTTP tambahan.

Cloudflare:

- Sistem mendeteksi marker seperti Just a moment, checking your browser, cf-chl, dan challenge-platform.
- Sistem dapat mencoba AsyncStealthySession.
- URL Analysis secara eksplisit menggunakan solve_cloudflare=false.
- Tidak ada jaminan challenge akan selesai.

CAPTCHA:

- Tidak ada CAPTCHA solver.
- Tidak ada workflow review khusus CAPTCHA.

Cookie consent:

- Tidak ada handler untuk klik tombol consent.
- Tidak ada persistent consent cookie.

JavaScript challenge:

- Dideteksi melalui status dan marker HTML.
- Stealth fallback dicoba pada mode yang mendukungnya.

Login:

- Tidak ada credential submission.
- Tidak ada session login.
- Tidak ada persistent browser profile.

Timeout:

- Collector /extract-url memiliki timeout bounded.
- PDF memiliki budget download dan parsing tersendiri.
- URL worker menggunakan timeout terpisah untuk Collector dan NLP.
- Manual Crawl menggunakan timeout per fetch dan NLP.
- Job dapat berakhir partial atau failed.

Connection error:

- Scrapling memiliki retry terbatas.
- RabbitMQ memiliki reconnect/publish retry.
- Bulk worker melakukan requeue sampai batas percobaan tertentu.
- Manual Crawl tidak memiliki retry umum per artikel.


7. CURRENT DEDUPLICATION
------------------------

Same URL pada continuous collector:

- db.is_url_already_processed() membandingkan raw_reports.url.
- Status PROCESSED dan NON_HEALTH dianggap selesai.
- Status FAILED tetap retryable.
- Worker memakai pg_advisory_xact_lock(hashtext(url)).
- Event lama dihapus lalu event terbaru dibuat kembali.

Same URL pada Direct URL Analysis:

- Backend Rust melakukan cache lookup berdasarkan exact raw_reports.url.
- Cache valid membutuhkan event dengan disease classification valid dan confidence minimal.
- Worker asynchronous memiliki cache lookup sendiri dan dapat memakai RAW partial.
- force_refresh dapat melewati cache.

Same URL pada Manual Crawler:

- Discovery hanya memakai in-memory set selama satu job.
- Tidak ada global URL dedup sebelum persist_article.
- Reprocess dapat membuat raw_reports baru.

Tracking parameters:

- Belum ditangani secara umum.
- Normalisasi hanya memperbaiki trailing slash sebelum query.
- Tidak ada penghapusan utm_source, utm_medium, utm_campaign, fbclid, gclid, dan sejenisnya.

Same article dari domain berbeda:

- Belum ada canonical URL matching.
- Belum ada title similarity atau content similarity.

Google News versus website asli:

- Belum ada mekanisme khusus untuk membuktikan bahwa keduanya adalah artikel yang sama.

Same content dengan URL berbeda:

- Belum ada content fingerprint global pada raw_reports.

Hash yang tersedia terutama digunakan untuk:

- Object path MinIO.
- Deduplikasi payload SKDR.
- Checkpoint social CSV.

Database raw_reports.url hanya memiliki index, bukan unique constraint.

Untuk URL-based collector message:

- RAW provisional dapat dibuat dengan status PROCESSING.
- Setelah NLP berhasil, status menjadi PROCESSED.
- Jika bukan konten kesehatan, status menjadi NON_HEALTH.
- Jika gagal permanen, status menjadi FAILED.

Jika NLP gagal:

- Request exception dicoba kembali melalui RabbitMQ requeue.
- Setelah tiga kegagalan, pesan di-acknowledge sebagai poison pill.
- RAW ditandai FAILED.
- Worker memiliki fallback ke endpoint /nlp/analyze/raw.
- Error database juga direqueue sampai batas percobaan.

Direct URL asynchronous:

    |
    v

    +--> Update analysis_jobs

Artikel dapat dilewati karena:

- URL sudah berstatus selesai pada continuous collector.

- Tidak memenuhi filter penyakit.
- Tidak memenuhi filter negara.
- Tidak memenuhi filter provinsi/kota.
- Tanggal di luar range Manual Crawler.
- Tidak memiliki metrik lokasi/kasus yang dapat dibuat menjadi matrix row.
- Terdeteksi non-health oleh pipeline.


9. CURRENT LIMITATIONS
----------------------

- Tidak ada recursive crawling atau link discovery.
- Tidak ada sitemap crawling.
- Tidak ada pagination website umum.
- Tidak ada infinite scroll.
- Manual Crawler discovery hanya Google News RSS atau URL langsung.
- Manual Crawler belum memakai seluruh collector_sources.
- Manual Crawler maksimal 50 artikel per job.
- Date range Manual Crawler diterapkan setelah extraction/NLP.
- Continuous RSS mengirim title dan summary, bukan full article.
- RSS/feedparser tidak memiliki timeout HTTP eksplisit yang dikontrol project.
- CSV collector tidak memiliki retry/backoff umum.
- Manual Crawl tidak memiliki retry per artikel untuk Collector/NLP.
- Tidak ada rate limiter per domain.
- Tidak ada robots.txt handling.
- Tidak ada persistent browser cookie/session.
- Tidak ada login/authentication flow untuk website target.
- Tidak ada cookie consent automation.
- Tidak ada CAPTCHA solver.
- Cloudflare hanya dideteksi dan dicoba melalui fallback.
- URL normalization belum menangani tracking parameter secara umum.
- Tidak ada global content deduplication.
- Tidak ada unique constraint pada raw_reports.url.
- Manual reprocess dapat membuat RAW baru.
- Jalur URL asynchronous dan synchronous memiliki perilaku berbeda.
- Rust API default async adalah false, sedangkan frontend mengirim async=true.
- SKDR code tersedia tetapi scheduler dan consumer dinonaktifkan.
- Twitter API tidak aktif jika Tweepy tidak tersedia.
- PDF scan belum diproses tanpa OCR.
- Beberapa HTTP fetch menggunakan verify=False.
- Implementasi crawler serupa masih ada di Collector dan Worker.


10. QUESTIONS FOR BUSINESS CONFIRMATION
---------------------------------------

Pertanyaan berikut tidak dapat dijawab hanya dari source code dan dapat mengubah target architecture:

1. Apa tujuan bisnis utama sistem ini: monitoring berita penyakit, early warning outbreak, pengumpulan data surveillance, atau kombinasi semuanya?

2. Untuk dashboard utama, sumber mana yang authoritative: SKDR, berita online, social media, Manual Crawler, atau gabungan dengan prioritas tertentu?

3. Apakah Continuous Crawl harus mengambil full content halaman artikel, atau cukup title dan summary dari RSS?

4. Untuk Continuous Crawl, apakah source harus terbatas pada collector_sources atau sistem harus menemukan source baru secara otomatis?

5. Untuk Manual Crawl, apakah pencarian hanya boleh berasal dari Google News atau harus mencakup RSS portal, website, API, dan social media?

6. Jika satu artikel membahas beberapa penyakit, apakah harus menjadi beberapa disease record, satu record utama, atau keduanya?

7. Jika artikel membahas beberapa negara/wilayah, apakah semuanya masuk matrix atau hanya negara yang dipilih user?

8. Untuk filter tanggal, apakah acuan bisnisnya tanggal publikasi, tanggal kejadian, tanggal laporan kasus, atau tanggal terbaru yang tersedia?

9. Jika artikel tidak memiliki tanggal yang dapat dipercaya, apakah harus dilewati, disimpan sebagai review, atau tetap masuk dashboard?

10. Jika URL yang sama diperbarui oleh publisher, apakah sistem harus mengganti hasil lama, menyimpan version history, atau membuat event baru?

11. Jika artikel yang sama muncul dari beberapa sumber, apakah dihitung sebagai satu artikel atau beberapa laporan dengan sumber berbeda?

12. Kapan artikel dianggap layak dikirim ke NLP: semua artikel, yang memiliki keyword penyakit, yang memiliki angka kasus, atau kombinasi aturan?

13. Jika extraction berhasil tetapi NLP gagal atau confidence rendah, apakah RAW tetap masuk dashboard, hanya masuk review queue, atau tidak boleh terlihat sebagai data surveillance?

14. Apakah website dengan login, paywall, CAPTCHA, Cloudflare challenge, atau cookie consent termasuk target yang diizinkan?

15. Berapa target freshness dan volume: jumlah source aktif, URL per hari, artikel per hari, waktu maksimal discovery sampai NLP, dan retention RAW?


11. IMPORTANT ASSUMPTIONS
-------------------------

- Sistem tampaknya diarahkan untuk disease surveillance berbasis berita, social media, dan data surveillance terstruktur.
- RAW berarti kombinasi record raw_reports di PostgreSQL dan object source tertentu di MinIO.
- Continuous Crawl, Direct URL Analysis, dan Manual Crawl menggunakan pipeline berbeda.
- Manual Crawler tampaknya ditujukan untuk membuat matrix kasus penyakit/lokasi, bukan sekadar mengumpulkan RAW.
- Google News berperan sebagai discovery engine utama Manual Crawler, bukan satu-satunya source continuous.
- Continuous RSS kemungkinan ditujukan untuk monitoring cepat karena NLP menerima summary RSS.
- Direct URL Analysis ditujukan untuk analisis interaktif satu artikel secara asynchronous.
- crawl_matrix_rows kemungkinan merupakan output bisnis utama Manual Crawler, sedangkan raw_reports berfungsi sebagai sumber audit.
- Disease filter Manual Crawler dianggap berbasis master ICD-11 aktif.
- Multiple disease pada Manual Crawler saat ini diperlakukan sebagai alternatif OR.
- ASEAN dan Global diperlakukan sebagai scope filter setelah extraction, bukan query literal.
- SKDR yang dinonaktifkan kemungkinan merupakan keputusan operasional sementara, tetapi alasan bisnisnya belum terlihat dari source code.
- Tidak ada bukti source code bahwa target bisnis membutuhkan recursive crawling, sitemap, atau infinite scroll.
- Tidak ada bukti source code mengenai target volume, SLA, retention, atau prioritas source organisasi.
