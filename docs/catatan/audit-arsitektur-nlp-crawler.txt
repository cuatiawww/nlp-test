NLP-PENYAKIT Crawling Architecture Audit

The system is a hybrid architecture with three ingestion lanes.

1. Current crawling flow

Continuous source crawling:
The collector scheduler loads enabled sources, selects a collector by source_type, fetches articles, stores raw artifacts in MinIO, and publishes processing messages to RabbitMQ.

2. URL deduplication and already-processed logic

- URL normalization lowercases scheme/host, removes tracking parameters and fragments, sorts query parameters, and generates URL hashes.
- Canonical URL, final URL, normalized URL, URL hash, and content hash are stored on raw_reports.
- Collector prechecks only consider PROCESSED and NON_HEALTH reports. Failed reports remain retryable.
- The bulk worker performs the final duplicate check under a PostgreSQL advisory lock.
- The matrix worker additionally uses crawler_nlp_cache keyed by identity hash and pipeline version.

Main weaknesses:
- Database identity fields have indexes but no unique constraints.
- Collector prechecks are fail-open on database errors and are not atomic with publishing.
- URL aliases can pass the collector precheck before the worker resolves their final/canonical identity.
- The legacy manual runner inserts raw records directly without the worker's full identity pipeline.

3. Worker and job flow

- disease.raw and disease.social are consumed by worker.py.
- Messages are marked PROCESSING, sent to /nlp/analyze/raw, then persisted as raw reports and disease events.
- Retryable failures are republished to retry queues with TTL and dead-letter routing.
- disease.analysis-url is handled by the dedicated analysis worker.
- disease.crawl-matrix is handled by the matrix worker, which also polls PostgreSQL for queued/stale jobs.

Relevant files:
- services/worker-python/app/worker.py:419

Notable issue:
Matrix RabbitMQ messages are acknowledged before the job is claimed or processed. PostgreSQL polling provides some recovery, but broker delivery is not coupled to successful execution.

SKDR is currently detached:
- Scheduler skips SKDR sources.
- RabbitMQ publisher skips SKDR messages.
- The NLP SKDR endpoint returns 410 Gone.
- The worker acknowledges and drops SKDR messages.

4. Article extraction and normalization

- RSS extraction parses feed metadata and optionally fetches full articles.
- Web extraction supports direct HTTP, stealth/browser fallback, PDFs, canonical links, OpenGraph metadata, JSON-LD, authors, publication dates, and trafilatura/HTML selector extraction.
- CSV and social collectors construct normalized article text and metadata.
- Raw HTML, PDF, CSV, and social artifacts are written to MinIO before publishing processing messages.
- Identity metadata is attached to messages for downstream deduplication.

5. Disease and country detection

The NLP pipeline:
- Repairs mojibake and normalizes text.
- Detects language and optionally translates non-Latin ASEAN languages.
- Extracts disease aliases, symptoms, WHO concepts, and disease mentions.
- Extracts locations and countries using aliases, gazetteer data, country boundaries, and optional geocoding.
- Separates article/event country from publisher/source country.
- Produces primary classification plus disease mentions and structured sub-events.

6. Storage and database flow

- raw_reports is the raw/source-of-truth record.
- MinIO stores fetched source artifacts.
- RabbitMQ carries processing jobs.
- NLP results become disease_events.
- Manual crawl-specific output becomes crawl_matrix_rows.
- crawler_nlp_cache prevents repeated NLP work.
- collector_runs, analysis_jobs, and crawl_matrix_jobs track execution state.

7. Current reliability problems

1. Continuous collection has no transactional outbox. MinIO upload occurs before RabbitMQ publish, so crashes or broker failures can create orphaned objects or lose processing messages.

2. Matrix queue acknowledgements occur before processing. A worker crash after ACK can leave execution dependent on the database poller.

3. Deduplication is distributed across collector prechecks, worker locks, matrix cache, and Rust persistence, with no database uniqueness constraint.

4. Identity locking is inconsistent: the worker initially locks by strongest identity, but later persistence may lock by the raw URL, allowing alternate URL forms to race.

5. The legacy manual runner, matrix worker, analysis worker, and Rust synchronous path implement overlapping persistence logic, creating behavior and schema drift.

6. Non-social worker messages without a current-year date are silently dropped. RSS collection also excludes undated/non-current records by default.

7. SKDR collection is effectively disabled and messages are dropped.

8. MinIO uploads are single-attempt operations, and collector publishing is best-effort.

9. Rate limiting and concurrency controls are process-local, so multiple collector replicas can exceed configured per-domain limits.

10. Existing PROCESSING raw reports have no clearly visible stale-record recovery equivalent to stale collector/job recovery.

11. The Rust synchronous URL path deletes existing raw/event data before reinserting the new result, creating data-loss risk if extraction, NLP, or persistence fails afterward.

Audit scope:
Read-only inspection of relevant crawler, collector, worker, NLP, backend integration, and database schema files. No files were modified. No tests were run.
